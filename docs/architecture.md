## Компоненты

| Компонент | Путь | Ответственность | Зависимости |
|---|---|---|---|
| `order-core` | `packages/core` | вся доменная логика: позиции, промокоды, скидки, доставка, ошибки | только стандартная библиотека |
| `order-api` | `app/api` | HTTP: приём запроса, преобразование в доменные объекты, ответ; выбор хранилища промокодов | `order-core`, FastAPI, uvicorn, psycopg |
| PostgreSQL | `infra/compose.yaml`, `infra/db/init.sql` | хранение промокодов | — |

### Граница между ядром и приложением

`order-core` не знает ни про HTTP, ни про базу данных, ни про переменные окружения.
Справочник промокодов передаётся в `calculate_receipt` параметром — поэтому то же
ядро можно вызвать из CLI, бота или пакетной обработки, а приложение может хранить
промокоды где угодно.

Ядро собирается отдельно (`make build-core` → wheel в `dist/`) и не требует для этого
запуска приложения. В Docker-образе ядро сначала собирается в wheel на отдельной
стадии и затем устанавливается в образ приложения как обычный пакет.

### Хранилище промокодов

Приложение работает с протоколом `PromoCodeRepository` (метод `all()`). Реализации:

- `InMemoryPromoCodeRepository` — встроенные промокоды; используется локально и в тестах;
- `PostgresPromoCodeRepository` — таблица `promo_codes`; включается переменной `DATABASE_URL`.

## Воспроизводимость

- Версия Python — `.python-version` (3.10), тот же образ `python:3.10-slim` в Docker.
- Прямые зависимости — в `*.in`, полное разрешённое окружение — в `*.lock`
  (отдельно для приложения, инструментов разработки и документации).
- Настройки контейнеров — через переменные окружения (`infra/.env.example`).
- Внутри compose-сети API обращается к базе по имени сервиса `db`.
- API ждёт готовности базы через `healthcheck` и `depends_on: condition: service_healthy`;
  данные базы — в volume `pgdata`.
